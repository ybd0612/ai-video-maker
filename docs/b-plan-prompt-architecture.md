# B 方案设计稿：中文主数据 + AI 派生提示词架构

> 状态：**设计稿，未实施**（等用户确认后动工）
> 日期：2026-09-12
> 背景诊断：「小白兔/兔妈定妆照生成人类」——风格图污染 → img2img 复制人物 → 人像语汇加重（详见当日工作日志）。

## 1. 产品目标（用户确立）

1. 一个想法 → AI 自动分析出**角色 / 场景 / 产品 / 风格**四类资产，自动生成名称 + 中文描述。
2. 中文是用户唯一需要关心的内容（**唯一事实源**）。
3. 英文正向 / 负向提示词全部由 **AI 根据中文内容派生**，不在代码里写死任何项目的具体内容；默认锁定、可解锁精修。
4. 系统规则层**不写死**（用户会不停调整）→ 采用「规则条目注册表」方案（见 §4）。
5. 生图请求结构遵循 Agnes Image 2.5 官方文档推荐（见 §2）。

## 2. 官方文档推荐结构（生图，2026-09 用户提供）

### 2.1 提示词推荐结构（AI 派生英文提示词的拼装依据）

| 模式 | 官方推荐结构 |
|------|-------------|
| 文生图 | `[主体] + [场景/环境] + [风格] + [光照] + [构图] + [质量要求]` |
| 图生图 | `[改变要求] + [新风格/新场景] + [需要添加或移除的元素] + [需要保留的元素]` |
| 多图合成 | `[参考图角色说明] + [目标场景] + [图像之间的关系] + [风格/光照/构图]` |
| 高信息密度图像 | 描述视觉层次：主要主体 → 背景 → 次要细节 → 风格 → 光照 → 构图 |

### 2.2 请求参数要点（与现状的差异）

| 参数 | 文档推荐 | 现状 | B 方案动作 |
|------|---------|------|-----------|
| `size` | 档位 `1K/2K/3K/4K` | 精确像素（如 `768x1344`，**非标准 9:16，会被服务端标准化**） | 改档位 + `ratio` |
| `ratio` | `1:1 / 3:4 / 4:3 / 16:9 / 9:16 / 2:3 / 3:2 / 21:9`（默认 1:1） | 无独立字段（折进 size） | 新增独立字段 |
| `extra_body.image` | 数组，URL 或 Data URI；支持图生图 1 张、多图合成多张 | 仅单张（数组形式已合规） | 扩展为多参考图 |
| `extra_body.response_format` | 必须放 extra_body | ✅ 已合规 | 无 |
| 负向提示词 | API 无独立 `negative_prompt` 参数 | 无 | 负向由 AI 决定拼接进正向的策略 |

参考像素（1K 档）：`9:16 → 736x1312`、`16:9 → 1312x736`、`1:1 → 1024x1024`。

## 3. 三层数据架构

```
L1 中文事实源（可编辑，persist）
  想法 ideaPrompt
  资产 assets[]：角色/场景/产品/风格 —— 名称 + 中文描述
  ※ 「风格」升级为一等资产（新 Asset type="style"）

L2 派生层（英文提示词，AI 生成 = 编译产物）
  characterAppearance  角色外貌锚点（物种词开头，六段式之「主体」）
  stylePrompt          风格提示词（画种/色调/光照/氛围，零角色）
  portraitPrompt       定妆照提示词（图生图结构，参考风格图）
  shotVisualPrompt     分镜图提示词（文生图六段式 / 多图合成结构）
  shotMotionPrompt     视频运动提示词
  negativeStrategy     负向拼接策略（拼进正向，不独立成参数）
  ※ 懒派生：改中文 → 标 dirty → 出图前统一重生成（省 token、无感等待）
  ※ 默认锁定；可解锁精修（解锁后该字段不再自动重生成，可手动「重新派生」）

L3 生成层（图像/视频请求）
  风格图：纯风格零角色（治本）
  定妆照：图生图结构 + 风格图参考 + 物种锁定
  分镜图：多图合成结构 + [定妆照/场景图/风格图] 多参考
```

### 3.1 六段式与项目字段的映射

| 文档段落 | 数据来源 |
|---------|---------|
| 主体 | 角色外貌锚点（L2 派生） |
| 场景/环境 | 场景资产描述（L1 → L2 派生英文化） |
| 风格 | 风格资产（L1 → L2 派生，全项目统一） |
| 光照 | 风格资产氛围 + 镜头 lightingDesc |
| 构图 | 镜头 cameraDesc / 画幅 |
| 质量要求 | 模板常量（规则条目，可编辑） |

## 4. 系统规则层：规则条目注册表（不写死的方案）

> 诉求：规则（如「动物也算角色」「物种词开头」「安全约束」）要能**不停修改**，不想每次改代码。

### 4.1 核心思路：骨架写死、规则数据化

系统提示词 = **骨架**（JSON 输出格式、字段定义——保证可解析、可测试，留在代码）+ **规则条目**（行为规则、示例、安全约束——变成数据条目，可随时增删改开关）。

```ts
// src/lib/promptRules.ts
export type PromptTask =
  | "extractAssets"        // 想法 → 资产提取
  | "storyboard"           // 分镜生成
  | "characterAppearance"  // 角色外貌派生
  | "styleRef"             // 风格提炼
  | "composeShot"          // 分镜图/运动提示词派生
  | "negativeStrategy";    // 负向拼接

export type PromptRule = {
  id: string;              // 如 "species-lock"
  task: PromptTask;        // 作用于哪个任务
  section: "rules" | "examples" | "safety";  // 渲染到骨架哪个插槽
  content: string;         // 规则文本
  enabled: boolean;
  source: "builtin" | "custom";
};
```

### 4.2 存储与拼装

- **内置默认集**（`BUILTIN_RULES`，代码内）：现在各系统提示词里的规则拆条目而来，作为**出厂兜底**，单元测试锁定其渲染结果。
- **自定义集**（settingsStore persist）：用户在设置界面增/删/改/开关，**即时生效，零构建**。
- `buildSystemPrompt(task, language, rules)`：骨架 + 生效条目按 section 插槽渲染（内置与自定义合并，同 id 自定义覆盖内置）。
- **兜底**：一键恢复默认；导入 / 导出 JSON（跨工具迁移、可让 AI 批量起草新条目）。
- **条目编辑用 AiPolishField**（复用现有润色/撤销模式）。

### 4.3 测试策略

- 锁**骨架结构**与**默认集渲染输出**（回归保护）。
- 自定义条目只测拼装逻辑（过滤/排序/覆盖），不锁内容。

## 5. 生成层改造要点

1. **风格图零角色**：风格提示词由文本模型从想法只提炼画种/色调/光照/氛围（`styleRef` 任务），硬性禁止出现角色/生物/人物；不再贴 idea 原文。
2. **定妆照**：图生图结构 + 参考风格图（单张）+ 物种词前置锁定 + 删除 `Portrait of / head and shoulders / looking at camera` 人像语汇 → `character design, full body`。
3. **分镜图多参考**：`extra_body.image` 传 `[场景参考图, 角色定妆照（activeCharacterIds 命中）, 风格图]`，prompt 按多图合成结构声明各参考图用途（参考图只作画风/形象锚点，勿复制构图）。
4. **参数**：`aspectRatioToImageParams` 返回 `{ size: "1K"|"2K", ratio }`；`ImageParams.inputImageUrl` → `referenceImageUrls: string[]`；`imageSizeToTier` 跟随档位。

## 6. 实施拆解（建议 4 个阶段，每阶段独立可验证）

| 阶段 | 内容 | 涉及 |

| 3 | 生成链路：风格图零角色、定妆照结构、多参考图、档位参数 | imageService、openai.ts、useWizardActions |

## 7. 兼容与迁移

- persist version + migrate：旧项目无 style 资产 → 首次进入资产步骤时从 ideaPrompt 派生补齐；旧 `prompt` 字段视为已有英文派生物（标记 locked，不强制重派生）。
- 9:16 尺寸切换到档位后实际像素变化（768x1344 → 736x1312），已生成图片不受影响，新生成图片与视频 720P 口径更接近。
- i18n：新增文案 zh/en 同步。

## 8. 验证口径

- AI 侧：`npx tsc --noEmit` + `git diff --check` + `npm run test` + `npm run build`。
- 拼装器/规则注册表/迁移必须补 Vitest 用例（禁浏览器测试，项目铁律）。
- 生成效果（兔子不再变人、风格贴合）由用户本地实测确认。
