# 竞品对标与能力缺口分析

日期：2026-09-21　｜　类型：演进规划（roadmap）　｜　状态：评审待决

对标对象：Runway（Gen-4 References / Storyboards / Aleph / 多模型聚合）、LTX Studio 与 LTX-2 提示词规范、Google Flow + Veo 3.1、可灵 / 即梦 Seedance、剪映图文成片与电商一键成片类产品。
对照基线：本仓库当前 6 步向导（想法 → 资产 → 分镜 → 图片 → 视频 → 成片）的四份流程快照文档。

结论只有一句：**单步生成能力已经具备，缺的是"镜头之间"和"画面之外"的两段。** 一致性靠人工挑参考图、成片是一段无声裸片、失败后无法补做单点、版本不可比 —— 这四点决定了目前是"能跑通的工具"，还不是"能交付成片的产品"。

---

## 一、提示词逻辑的缺口

| # | 缺口 | 我们现在 | 竞品做法 | 建议 |
|---|---|---|---|---|
| P1-1 | **镜头没有"景别/机位"这一层** | 画面提示词是主体+场景+风格+光影+构图的并列文本，景别和运镜混在一起 | 把景别当作第一个定框要素（Wide / Medium / OTS / Extreme close-up），再写环境与动作；机位与稳定方式单独成句（tripod-locked、slow push in、handheld drift） | 给镜头增加「景别」与「机位/稳定」两个受控词表字段，拼装时置于句首；词表内置、可在规则里扩展 |
| P1-2 | **镜头内没有时间推进结构** | 时长只有 4/5/8 秒，提示词是一句静态描述，模型自己决定何时做什么 | 在提示词里写时间码分段（0–3s 做 A，3–5s 做 B），长片段按"小剧本"写 | 时长 ≥5 秒的镜头自动要求 2–3 个顺序动作并标注时间区间；短镜头强制"只写一个动作"，避免元素过载 |
| P1-3 | **音频完全没有进入提示词链** | 对白有说话人、台词、演绎方式三要素，但不进任何请求；没有音效、环境声、配乐的概念 | 主流视频模型已把原生音频当一等公民（对白、音效、环境声、音乐同次生成），音频也可单独生成长达两分钟的语音/音效/配乐 | 先确认所用模型是否支持音频与口型。支持 → 把对白、必要音效、环境声写入视频提示词，并在镜头卡上区分"有声/无声"；不支持 → 明确标注限制，走字幕 + 后期配音方案（见 P0-3） |
| P1-4 | **缺少镜头级"守卫句"** | 负向策略只有一段全局文本，注入方式与正向约束混在一起 | 按镜头追加具体防漂移守卫：身份不变、不遮挡脸部、不做叠化与形变、不要画面内文字与高频纹理 | 增加镜头级守卫槽位（默认继承全局 + 可逐镜头追加），拼装时单独成段，不与风格句混排 |
| P1-5 | **情绪落成画面动作的规则缺失** | 情绪只存在于视觉方向与文案里，画面提示词不要求把它变成可见线索 | 官方明确把"只写情绪标签、不给可见线索"列为反模式，要求改写为表情与肢体动作 | 细化时增加一条硬要求：文案里的每个情绪词必须映射为可见动作/表情/姿态；否则要求模型补全 |
| P1-6 | **产品广告场景的文字与 Logo 没有专门策略** | 资产里有"品牌或 Logo"字段，但它直接进生图文本，而模型画不准可读文字 | 通用规则是"不要在画面里要求可读文字与标志" | 品牌信息改为两条路：① 提示词里只描述形态/材质/配色，不要求可读文字；② Logo 与卖点文字走拼接阶段叠加（需要 P0-3 的叠加能力）。当前是两者都没做 |
| P1-7 | **场景信息在参考图链路上被完全丢弃** | 场景图不再生成分镜参考（会被整体复制），环境信息只剩资产文字描述 | 参考图按角色分工（角色=脸/服装、物体=主体、场景=地点/光照/镜头质感/色调），并用"matching Image 3"式短语逐项对齐 | 加一个"图→文"桥：把场景参考图先转写成英文环境描述，再以文字注入镜头提示词。既不丢环境信息，也不复制构图 |
| P1-8 | **多参考图缺少"引用锚定"短语** | 已支持多张参考图并说明第几张是什么角色 | 每张参考图先定义职责，再在正文中用固定短语指回它，并显式禁止漂移 | 现有模板上补两点：每个子句显式指回参考图序号；追加一致性禁止句 |
| P2-9 | **提示词长度没有预算控制** | 只有输出侧 token 预算；多参考 + 风格 + 规则叠加后输入长度无人管 | 指南普遍强调"少即是稳"，元素过载是首要反模式 | 拼装时统计并展示长度，超阈值按优先级裁剪（守卫句 > 景别 > 主体 > 风格重复描述） |

## 二、生成流程逻辑的缺口

| # | 缺口 | 我们现在 | 竞品做法 | 建议 |
|---|---|---|---|---|
| **P0-1** | **镜头之间没有连续性链** | 尾帧要用户手动开关、手动点选，默认所有镜头各自独立生成 → 成片镜头之间人物/光照/构图跳变 | 首尾帧是标准控制手段，实操就是取上一段末帧作下一段首帧，并要求同场景、同身份、同色板、同布光；此外还提供中间关键帧控节奏、片段续接 | 增加"自动衔接"开关：按场景分组，把同场景相邻镜头串成首尾帧链；不满足同场景条件时明确断开并提示原因（这是目前对成片质量提升最大的一项） |
| **P0-2** | **失败与失效之后无法定点补做** | 改动会让镜头图片被清空并退回"文案就绪"，但补生成入口只在挂载时自动触发，失败态才显示重试按钮 → 用户只能整套全部重做 | 支持"改一帧整段跟随"、只重做单镜头/单区域、失败项集中列示与批量重做 | 三处补齐：① 被失效的镜头在列表里有独立状态与"补做这一个"按钮；② 顶部"重试失败"扩展为"重试缺失与失败"；③ 提供区域级/元素级修补入口（有则接，无则先做整镜头重做） |
| **P0-3** | **成片是一段裸片：无字幕、无配音、无配乐、无转场、无音量归一** | 拼接只做顺序 concat，唯一收尾是导出 MP4；单镜头时甚至跳过剪辑环节 | 一键成片类产品的最低配置都包含口播配音、自动字幕、BGM 与卡点转场；音频可独立生成 | 把成片从"concat"升级为"最小可发布成片"：字幕轨（由对白与文案生成）、BGM 与音量归一、镜头间短交叉淡化、片尾卡。先做不依赖模型能力的部分（字幕 + 音乐 + 转场 + 归一） |
| **P1-4** | **没有版本与多方案对比** | 重做直接覆盖，旧图旧视频不可回溯；没有"同提示词多版本挑优"的概念（随机种子只在角色定妆照用到） | 同一镜头生成多条 take 供挑选，保留历史版本，可回看可切换采用 | 镜头层引入版本列表（含随机种子与提示词快照），支持并排对比后"采用此版本"；重做不再破坏已采用版本 |
| **P1-5** | **没有成本预估与返还** | 配额在发起前就扣，失败不回滚；非幂等的生图与生视频仍会自动重试 → 可能重复计费。视频步骤只显示待消耗秒数 | 主流产品统一是"预估积分 → 确认 → 失败返还"，且任务与积分流水可追溯 | 做三件事：① 步骤级"预计消耗 X 张图 / Y 秒视频"总预算与二次确认；② 失败自动返还积分；③ 用量台账可追溯到镜头 |
| **P1-6** | **长任务不可取消、不可续跑** | 除成片拼接外没有任何取消入口；切项目、离开步骤、刷新都不会中断在飞请求与轮询，刷新后也不恢复轮询 | 任务队列可见、可取消、可重试，页面刷新不丢任务状态 | 补取消按钮 + 后台任务提示条（"3 个镜头仍在生成"）+ 刷新后恢复轮询与进度 |
| **P1-7** | **一致性只靠提示词禁止，没有质量闸口** | 靠"不要出现人物"之类的文本约束，生成后无人校验 | 以参考图锚定 + 布局草图控制构图；靠人工挑 take | 在图片步骤加一道轻量质检卡点：与角色定妆照并排比对、支持"标记不一致"，标记项在视频步骤默认排除（可选：接相似度打分做自动预警） |
| **P1-8** | **没有目标时长/平台这一层的约束** | 镜头数与每镜时长各自有规则，但全片目标时长、平台约束、节奏分布无人管；镜头数口径在文档与提示词里还不一致 | 规划阶段就问目标时长、平台与画幅，并据此约束镜头数量与节奏 | 在想法步骤采集"目标时长 + 发布平台"，大纲据此分配镜头数与时长，成片校验总时长是否达标 |
| **P2-9** | **导出物不完整** | 只导出 MP4，没有字幕文件、分镜表、工程备份 | 支持工程导出/导入与团队协作版本 | 增加字幕文件、分镜表（可交付给剪辑）、工程 JSON 备份与导入 |
| **P2-10** | **首次使用门槛** | 无模板，用户必须从一句想法开始 | 提供题材模板、风格预设与示例工程 | 上线 5–10 个可直接复制的示例工程与风格预设，并支持"换个题材复用同一套结构" |

## 三、可以先做的三件小事（低成本、收益明确）

1. **让资产提取看到视觉方向。** 代码本来就留了入参，只是调用点没传；两步并行导致资产外观与母版画风各画各的，现在只能靠生图时的文字补偿。改成视觉方向先完成再提资产，代价是多等一次调用。
2. **把"景别"从运镜里独立出来。** 只动词表与拼装顺序，不动模型、不加依赖，但直接改善镜头语言是否像分镜。
3. **成片加一条字幕轨与一首 BGM。** 完全不需要模型能力，只改拼接环节，就能把"能看"变成"能发"。

## 四、开工前必须先确认的事

- 所接视频模型是否支持：原生音频与对白、口型同步、尾帧/中间关键帧、单次最长时长、分辨率档位。这几项决定 P0-1、P1-3、P0-3 是"接能力"还是"绕路做"。
- 是否允许并行多版本（同镜头多次生成）：决定 P1-4 的成本策略与默认值。
- 镜头数与总时长的产品口径统一到哪一档（4-6 还是 4-8，目标时长是否可配）。
