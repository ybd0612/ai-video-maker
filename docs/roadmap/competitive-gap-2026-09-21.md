# 竞品对标与能力缺口分析

日期：2026-09-21　｜　类型：演进规划（roadmap）　｜　状态：评审待决

对标对象：Runway（Gen-4 References / Storyboards / Aleph / 多模型聚合）、LTX Studio 与 LTX-2 提示词规范、Google Flow + Veo 3.1、可灵 / 即梦 Seedance、剪映图文成片与电商一键成片类产品。
对照基线：本仓库当前 6 步向导（想法 → 资产 → 分镜 → 图片 → 视频 → 成片）的四份流程快照文档。

结论只有一句：**单步生成能力已经具备，缺的是"镜头之间"和"画面之外"的两段。** 一致性靠人工挑参考图、成片是一段无声裸片、失败后无法补做单点、版本不可比 —— 这四点决定了目前是"能跑通的工具"，还不是"能交付成片的产品"。

## 一、提示词逻辑的缺口

| # | 缺口 | 我们现在 | 竞品做法 | 建议 |
|---|---|---|---|---|
| P1-1 | **镜头没有"景别/机位"这一层** | 画面提示词是主体+场景+风格+光影+构图的并列文本，景别和运镜混在一起 | 把景别当作第一个定框要素（Wide / Medium / OTS / Extreme close-up），再写环境与动作；机位与稳定方式单独成句（tripod-locked、slow push in、handheld drift） | 给镜头增加「景别」与「机位/稳定」两个受控词表字段，拼装时置于句首；词表内置、可在规则里扩展 |
| P1-2 | **镜头内没有时间推进结构** | 时长只有 4/5/8 秒，提示词是一句静态描述，模型自己决定何时做什么 | 在提示词里写时间码分段（0–3s 做 A，3–5s 做 B），长片段按"小剧本"写 | 时长 ≥5 秒的镜头自动要求 2–3 个顺序动作并标注时间区间；短镜头强制"只写一个动作"，避免元素过载 |
| P1-3 | **音频完全没有进入提示词链** | 对白有说话人、台词、演绎方式三要素，但不进任何请求；没有音效、环境声、配乐的概念 | 主流视频模型已把原生音频当一等公民（对白、音效、环境声、音乐同次生成），音频也可单独生成长达两分钟的语音/音效/配乐 | 先确认所用模型是否支持音频与口型。支持 → 把对白、必要音效、环境声写入视频提示词，并在镜头卡上区分"有声/无声"；不支持 → 明确标注限制，走字幕 + 后期配音方案（见 P0-3） |
| P1-4 | **缺少镜头级"守卫句"** | 负向策略只有一段全局文本，注入方式与正向约束混在一起 | 按镜头追加具体防漂移守卫：身份不变、不遮挡脸部、不做叠化与形变、不要画面内文字与高频纹理 | 增加镜头级守卫槽位（默认继承全局 + 可逐镜头追加），拼装时单独成段，不与风格句混排 |
| P1-5 | **情绪落成画面动作的规则缺失** | 情绪只存在于视觉方向与文案里，画面提示词不要求把它变成可见线索 | 官方明确把"只写情绪标签、不给可见线索"列为反模式，要求改写为表情与肢体动作 | 细化时增加一条硬要求：文案里的每个情绪词必须映射为可见动作/表情/姿态；否则要求模型补全 |
| P1-6 | **产品广告场景的文字与 Logo 没有专门策略** | 资产里有"品牌或 Logo"字段，但它直接进生图文本，而模型画不准可读文字 | 通用规则是"不要在画面里要求可读文字与标志" | 品牌信息改为两条路：① 提示词里只描述形态/材质/配色，不要求可读文字；② Logo 与卖点文字走拼接阶段叠加（需要 P0-3 的叠加能力）。当前是两者都没做 |
| P1-7 | **场景信息在参考图链路上被完全丢弃** | 场景图不再生成分镜参考（会被整体复制），环境信息只剩资产文字描述 | 参考图按角色分工（角色=脸/服装、物体=主体、场景=地点/光照/镜头质感/色调），并用"matching Image 3"式短语逐项对齐 | 加一个"图→文"桥：把场景参考图先转写成英文环境描述，再以文字注入镜头提示词。既不丢环境信息，也不复制构图 |
| P1-8 | **多参考图缺少"引用锚定"短语** | 已支持多张参考图并说明第几张是什么角色 | 每张参考图先定义职责，再在正文中用固定短语指回它，并显式禁止漂移 | 现有模板上补两点：每个子句显式指回参考图序号；追加一致性禁止句 |
| P2-9 | **提示词长度没有预算控制** | 只有输出侧 token 预算；多参考 + 风格 + 规则叠加后输入长度无人管 | 指南普遍强调"少即是稳"，元素过载是首要反模式 | 拼装时统计并展示长度，超阈值按优先级裁剪（守卫句 > 景别 > 主体 > 风格重复描述） |

## 二、生成流程逻辑的缺口

| # | 缺口 | 我们现在 | 竞品做法 | 建议 |
|---|---|---|---|---|
| **P0-1** | **镜头之间没有连续性链** | 尾帧要用户手动开关、手动点选，默认所有镜头各自独立生成 → 成片镜头之间人物/光照/构图跳变 | 首尾帧是标准控制手段，实操就是取上一段末帧作下一段首帧，并要求同场景、同身份、同色板、同布光；此外还提供中间关键帧控节奏、片段续接 | 增加"自动衔接"开关：按场景分组，把同场景相邻镜头串成首尾帧链；不满足同场景条件时明确断开并提示原因（这是目前对成片质量提升最大的一项） |
| **P0-2** | **失败与失效之后无法定点补做** | 改动会让镜头图片被清空并退回"文案就绪"，但补生成入口只在挂载时自动触发，失败态才显示重试按钮 → 用户只能整套全部重做 | 支持"改一帧整段跟随"、只重做单镜头/单区域、失败项集中列示与批量重做 | 三处补齐：① 被失效的镜头在列表里有独立状态与"补做这一个"按钮；② 顶部"重试失败"扩展为"重试缺失与失败"；③ 提供区域级/元素级修补入口（有则接，无则先做整镜头重做） |
| **P0-3** | **成片是一段裸片：无字幕、无配音、无配乐、无转场、无音量归一** | 拼接只做顺序 concat，唯一收尾是导出 MP4；单镜头时甚至跳过剪辑环节 | 一键成片类产品的最低配置都包含口播配音、自动字幕、BGM 与卡点转场；音频可独立生成 | 把成片从"concat"升级为"最小可发布成片"：字幕轨（由对白与文案生成）、BGM 与音量归一、镜头间短交叉淡化、片尾卡。先做不依赖模型能力的部分（字幕 + 音乐 + 转场 + 归一） |
| **P1-4** | **没有版本与多方案对比** | 重做直接覆盖，旧图旧视频不可回溯；没有"同提示词多版本挑优"的概念（随机种子只在角色定妆照用到） | 同一镜头生成多条 take 供挑选，保留历史版本，可回看可切换采用 | 镜头层引入版本列表（含随机种子与提示词快照），支持并排对比后"采用此版本"；重做不再破坏已采用版本 |
| **P1-5** | **没有成本预估与返还** | 配额在发起前就扣，失败不回滚；图片与视频创建的服务层自动重试均已关闭（2026-09-23），但视频步骤编排层仍会在创建抛错时重发（最多 3 次）→ 仍可能重复计费。视频步骤只显示待消耗秒数 | 主流产品统一是"预估积分 → 确认 → 失败返还"，且任务与积分流水可追溯 | 做三件事：① 步骤级"预计消耗 X 张图 / Y 秒视频"总预算与二次确认；② 失败自动返还积分；③ 用量台账可追溯到镜头 |
| **P1-6** | **长任务不可取消、不可续跑** | 除成片拼接外没有任何取消入口；切项目、离开步骤、刷新都不会中断在飞请求与轮询，刷新后也不恢复轮询 | 任务队列可见、可取消、可重试，页面刷新不丢任务状态 | 补取消按钮 + 后台任务提示条（"3 个镜头仍在生成"）+ 刷新后恢复轮询与进度 |
| **P1-7** | **一致性只靠提示词禁止，没有质量闸口** | 靠"不要出现人物"之类的文本约束，生成后无人校验 | 以参考图锚定 + 布局草图控制构图；靠人工挑 take | 在图片步骤加一道轻量质检卡点：与角色定妆照并排比对、支持"标记不一致"，标记项在视频步骤默认排除（可选：接相似度打分做自动预警） |
| **P1-8** | **没有目标时长/平台这一层的约束** | 镜头数与每镜时长各自有规则，但全片目标时长、平台约束、节奏分布无人管；镜头数口径在文档与提示词里还不一致 | 规划阶段就问目标时长、平台与画幅，并据此约束镜头数量与节奏 | 在想法步骤采集"目标时长 + 发布平台"，大纲据此分配镜头数与时长，成片校验总时长是否达标 |
| **P2-9** | **导出物不完整** | 只导出 MP4，没有字幕文件、分镜表、工程备份 | 支持工程导出/导入与团队协作版本 | 增加字幕文件、分镜表（可交付给剪辑）、工程 JSON 备份与导入 |
| **P2-10** | **首次使用门槛** | 无模板，用户必须从一句想法开始 | 提供题材模板、风格预设与示例工程 | 上线 5–10 个可直接复制的示例工程与风格预设，并支持"换个题材复用同一套结构" |

## 三、可以先做的三件小事（低成本、收益明确）

1. **让资产提取看到视觉方向。** 代码本来就留了入参，只是调用点没传；两步并行导致资产外观与母版画风各画各的，现在只能靠生图时的文字补偿。改成视觉方向先完成再提资产，代价是多等一次调用。
2. **把"景别"从运镜里独立出来。** 只动词表与拼装顺序，不动模型、不加依赖，但直接改善镜头语言是否像分镜。
3. **成片加一条字幕轨与一首 BGM。** 完全不需要模型能力，只改拼接环节，就能把"能看"变成"能发"。

## 四、官方文档已确认的事实（原"待确认"清单已被推翻，结论比跑样片更省事）

查 Agnes 视频模型集成文档（`agnes-video-2.5-flash`，与 2.5 除 Flash 特例外参数一致）后，原先标为"要先问模型"的事项全部有确定答案：

| 项目 | 官方结论 | 我们现在的做法 |
|---|---|---|
| 模式 | `mode` 支持 `text` / `keyframe` / **`reference`** 三种 | 只用了 `text` 与 `keyframe`（`videoService.ts:149`） |
| 主体参考 | `reference` 模式支持 `images`（**最多 5 张**）与 `audios`（最多 3 条）；`videos` 不支持，传了直接 400 | **完全未使用** |
| 首尾帧 | `keyframe` 支持 `first_frame` / `last_frame`，至少给一个 | 已用，但尾帧要用户手动勾选并手选图片 |
| 分辨率 | Flash 锁定 `720P`（2.5 非 Flash 可到 1080P/2K） | 硬编码 `720P`，与 Flash 限制一致，不是缺陷 |
| 时长 | `seconds` 为字符串 `"4"`–`"12"`，默认 `"5"` | 一致（4/5/8 是产品层规则，再 clamp 4..12） |
| 画幅 | `21:9/16:9/4:3/1:1/3:4/9:16` | 白名单一致 |
| 轮询 | `keyframe` 与 `reference` **必须带 `model_name`** | 已带（代码注释还提到 reference，说明当时已知有此模式但从未实现） |
| 提示词锚定 | 提示词内可用 `<Picture N>` / `<Audio N>` 标记指代所给参考媒体 | 无此机制（P1-8 的官方落点就在这里） |
| 音频 | 无独立对白/音效字段，但可送 `audios` 参考，或在提示词里描述声音 | 对白只存不用（P1-3 因此从"待确认"变成"可动手"） |

**由此重排优先级：最大的缺口不是首尾帧，而是 `reference` 模式整条没接。**

竞品的一致性核心是"主体参考图驱动"（Runway Gen-4 References、Veo ingredients、可灵多模态参考），而我们目前把一致性全押在"首帧=上一阶段生成的图片"上 —— 于是图片阶段的小偏差会被视频阶段放大，也正是"角色图不能进参考图"两难的来源：在生图里参考图会复制构图，但在生视频里 `reference` + `images` 表达的语义是"保持这个主体身份"，与锁构图并不冲突。**这两件事被混在同一个机制里处理了。**

## 五、同场景首尾帧自动链的实测情况

派生逻辑已落地（`src/lib/shotContinuity.ts` + 13 条单测）。关键工程约束：`useDualFrame` 与 `lastFrameUrl` 属于 MOTION_SHOT_FIELDS，**写回会清空已生成视频**，所以衔接必须在发请求时派生、不持久化。

在一条 10 镜 / 4 场景的样例上实测：**只有 4 个相邻接缝可自动衔接**，其余断开原因分别是换场景（2 个）、同场景换人（1 个）、下一镜或本镜缺图（2 个）、末镜（1 个）。结论是直的：**这一招只治同场景内的跳，跨场景接缝它无能为力** —— 跨场景本就该切镜，靠拼接阶段的短转场更合适。

验证有效性做过变异测试：把同场景判定反转后，4 条用例立即失败（不是空跑的绿）。

## 六、真实 API 对照实验（2026-09-21 实测，免费档）

实验设计：同一张角色定妆照 + 同一镜头内容，跑两条 5 秒视频 —— V1 走现行 `mode=keyframe` + `first_frame=镜头图`，V2 走 `mode=reference` + `images=[定妆照]`（**不给任何首帧**）。用 ffmpeg 抽首/中/末帧逐帧比对身份、画风、构图与解剖稳定性。

| # | 实测结论 | 依据 |
|---|---|---|
| 1 | **`reference` 模式在 `agnes-video-2.5-flash` 上可用**，带 `images` 数组正常创建并出片，没有 400 | V2 任务 `task_z7igbqb5…` 完成，成片 1.5 MB / 5.18 秒 |
| 2 | **`reference` 是"身份锚"，不是"构图锁"**：只给定妆照时，白兔、红针织围巾、琥珀眼、胡须全程稳定，但构图由文本决定（变成侧脸特写、罐子移到右侧） | V2 首/中/末帧比对 |
| 3 | **`reference` 不携带画风**：V2 画风比定妆照更赛璐璐、描边更重 | V2 与定妆照并排比对 |
| 4 | **现行 keyframe 路径等于"给静帧加动效"**：V1 首帧与镜头图几乎像素一致，因此图片阶段的一切偏差被完整继承进视频 | V1 首帧 vs 镜头图 |
| 5 | **一致性在步骤 4 就已经丢过一次**：以定妆照为参考图生成的镜头图，画风相对定妆照明显漂移（毛发质感更细、加了胡须与眼影、构图重排） | 定妆照 vs 镜头图 |
| 6 | 成片地址在响应**顶层 `url`**，该响应没有 `metadata.url`；`seconds` 请求 "5" 实得 5.175 / 5.184 秒 | 完成响应字段清单 |
| 7 | 免费档视频 RPM=1 下，两次创建间隔 65 秒未触发 429；轮询带 `model_name` 正常 | 实验时间线 |

**据此修正优先级：`reference` 模式 > 首尾帧自动链。** 前者治的是"跨镜头是不是同一个角色"，后者只治"相邻两镜接得上"。而且第 3、5 条给出了一个新的可测组合：`images` 官方允许最多 5 张，那么 **`images=[定妆照, 风格母版]`** 能否同时锁住身份与画风 —— 如果成立，就能把"角色图不能进参考图"这个两难从生图阶段挪到生视频阶段解决。

下一轮待测变体：① `images=[定妆照, 风格母版]` 的画风保持力；② `reference` 与 `first_frame` 能否同时给（文档把两者归为不同 mode，疑似互斥，需实测确认）；③ `audios` 传入配音后的口型与音画同步表现。

### 6.1 第二轮实测（同日，V3–V6，已全部结案）

| 变体 | 结果 | 判定 |
|---|---|---|
| **V3** `reference` + `images=[定妆照, 风格母版]` | 成功出片 | **两张参考图可用，且画风与色板被带上**：成片呈母版的奶油/赤陶/琥珀/鼠尾草绿配色与平涂质感，明显比只给定妆照的 V2 更贴母版。结论：**"参考图会复制内容"这个两难只存在于生图阶段，生视频阶段可以同时锚身份与画风** |
| **V4** `keyframe` + `first_frame=镜头2图` + `last_frame=镜头3图` | 成功出片 | **末帧准确落在镜头3的目标构图上**（侧身、前爪搭罐、橱柜与窗光位置一致，仅裁切略有差异）。**自动首尾帧链的假设成立**，且不需要抽帧能力 —— 用下一镜的画面图当尾帧即可 |
| **V5** `reference` + `images` + `first_frame` 同时给 | **HTTP 400** | 服务端明确拒绝：`首尾帧素材与参考素材不能同时使用`（`data.param = "mode"`）。**两种一致性策略互斥，必须二选一**，不能叠加 |
| **V6** `audios` 音频参考 | 跳过 | 中国站无可用语音合成端点（`POST /audio/speech` → 503 `model_not_found`），拿不到真实配音素材。**口播/对白必须走外部 TTS 或后期方案** |

### 6.2 由此可定的三条落地决策

1. **视频阶段引入双参考图模式**：`images=[出场角色定妆照, 风格母版]`（上限 5 张，可容纳多角色镜头）。它替代"只能靠首帧继承一致性"的现状，且不受生图阶段复制问题的牵连。
2. **一致性策略要做成二选一开关**，不是叠加：`keyframe`（锁画面起止，适合同场景衔接与首尾帧链）与 `reference`（锁身份画风，适合跨场景保持角色）互斥，必须由代码按镜头关系选择或让用户显式设定。
3. **首尾帧自动链可以直接做**：V4 已证明有效，且实现上只需"取下一镜的画面图当本镜尾帧"，不需要抽帧、不需要新模型能力 —— 与 `src/lib/shotContinuity.ts` 的设计一致，剩下的只是把它接到请求侧并定下与 `reference` 模式的优先级规则。
