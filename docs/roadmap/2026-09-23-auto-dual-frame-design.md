# 双帧（首尾帧）自动化方案 —— 设计讨论稿

> 状态：**讨论稿，未开工**。本轮不改任何代码，供决策研究用。
> 关联：`docs/roadmap/2026-09-23-film-quality-fix-plan.md`（裁定 2 已把自动衔接方向反转）、`docs/execution-flow.md` §9、`AGENTS.md` 视频一致性策略段。

## 1. 这个词在产品里到底是什么

视频接口允许一段生成同时收到两张静帧：`first_frame`（起点画面）和 `last_frame`（终点画面），模型只负责补中间过程。界面上对应步骤 5「使用双图流（首尾帧控制）」勾选 + 一个尾帧图地址输入框。

它能买到的一件事：**强制这段视频结束在你指定的画面上**（例如「门必须已经打开」「猫必须已站在水塔顶」）。不给尾帧时，收尾由模型按运动提示词的概率自己决定。

它买不到的：跨镜头的衔接连续性。**这件事现在由另一条腿承担**——后镜的首帧取前镜视频的末帧（本地抽帧），与双帧无关。

## 2. 为什么现在它是纯手动的（不是漏做）

历史上它"自动"过一次：把**下一镜的画面图**当本镜尾帧。2026-09-23 逐帧取证实测（11 镜 / 7 处自动链接）证明这是方向错误：某镜首帧无水桶无水塔、猫额头一条黑发带，尾帧（＝下一镜画面）凭空长出红桶与水塔、眼罩换形态，8 秒内模型只能硬造机位位移与物体增减，且与该镜「全程无推拉摇移」的运动提示词直接对打 —— 这就是用户看到的「跳」。该路径已随裁定 2 拆除。

所以当前口径是：**尾帧只剩一个来源＝用户手动**；自动路径不再产生任何尾帧请求。这是收口，不是缺口。

## 3. 目标与非目标

**目标**
- 让"要不要双帧"和"尾帧是哪张图"在**有把握的镜头上自动成立**，用户零操作也能得到合理结果。
- 保留用户覆盖：手动勾选与手输 URL 永远优先于自动判断。
- 操作面只减不增：不新增第五个设置页。

**非目标**
- 不用双帧去解决跨镜头接缝（那是前镜末帧的职责）。
- 不承诺"每个镜头都有尾帧"——判定为无状态变化的镜头就该走单帧。
- 本方案不解决角色识别特征（眼罩）跨镜漂移，那是模型能力边界，另有条目化缓解。

## 4. 语义正确的前提

自动尾帧必须是**同一镜头、同一机位、同一景别**下"本镜动作完成后"的那一帧。由此推出两个硬要求：

1. **要有一张"结束态"的静帧**。目前每镜只出一张图，且它就是运动提示词的起幅（起点）。要自动尾帧，就得让分镜多产出一个"结束态画面"描述，并真的多生一张图。
2. **要有一台判断"这镜值不值一张额外图"的闸**。判据是叙事性的（本镜内是否存在可见的状态变化：开/关、站立/趴卧、空/满、干/湿），不是画面相似度。

只要绕开其中任一条，就会退回到第 2 节那个已被实测否决的做法。

## 5. 候选方案对比

| 方案 | 做什么 | 新增成本 | 主要风险 | 结论 |
|---|---|---|---|---|
| **A 全链路自动双帧** | 模型判 `needsDualFrame` + 出"结束态"描述 → 命中的镜头**多生一张尾帧图** → 视频自动带双帧，用户可覆盖 | 每个命中镜头 +1 次 1K 生图（既有实测口径：单张 29–59s，会随并发与限流浮动） | ① 模型滥判成"每镜都要双帧"→ 图片量近乎翻倍；② 两张静帧可能画出主体不一致（身份/服饰/道具漂移），反而制造新的"跳"；③ 与自动衔接抢素材，优先级要重定 | 方向正确，但**不要一步到位** |
| **B 只判定不生图（建议的第一步）** | 只让模型输出判定与"结束态"描述，界面标出「这镜建议双帧」并**预填**描述，不自动生图、不改请求体 | 纯文本，零额外计费 | 判定质量无数据；用户可能嫌提示噪音 | ✅ 先用它把"模型判得准不准"这件事变成可观测的事实 |
| **C 维持现状** | 双帧纯手动 | 0 | 用户要理解并逐镜操作 | 保底可回退态 |
| **D 拿下一镜画面当尾帧** | 旧实现 | 0 | 已被实测否决（凭空造位移 → 跳） | ❌ 禁止复活 |

### 推荐（本稿的判断）

**现在只做 B；A 视 B 的数据再决定；C 是可接受的稳态，不丢人。**

理由（按权重）：
1. **A 要解决的问题已被裁定 2 解决掉大半**。双帧如今只剩"镜头内动作没收住"这一条窄收益，而它最可能引入的新缺陷（同镜两张静帧分开生成 → 主体/道具/天气各画一份）正是这一轮花力气压下去的那类问题。用一个能制造同类缺陷的手段去换一点窄收益，不划算。
2. **B 的失败模式可观测且免费**。最大概率的失败是"模型给每个镜头都判需要双帧"，B 阶段就能从日志看出来，一分钱配额不花。
3. **成本是结构性的**：命中镜头各多一张 1K 图（既有实测口径：单张 29–59s，图片并发 3，免费档更慢），步骤 4 的墙钟时间与出图量按命中比例线性上涨，而收益只在个别镜头上看得见。

**决策规则（B 跑完 3–5 个真实项目后判）**
- 判定结果有明显区分度（不是全判"是"），且每条理由都能在成片里指认出一个具体状态变化 → 再考虑 A。
- 否则停在 C：双帧就是一项高级手动工具，界面保持现状。
- 不设"命中率必须低于某百分比"这类硬阈值——那是拍脑袋数字，且会诱导把判定写松。

### B 的具体形态（如果只做一步，就做这个）

- 分镜阶段每镜多两个产出：`是否需要双帧`（是/否 + 一句话理由）与 `结束态画面`（一句中文静帧描述，与起幅同机位同景别）。
- 步骤 5 的镜头卡片上，判定为"是"的镜头显示一枚标记（例：「AI 建议：这镜有状态变化，可补尾帧」），点开即见预填好的结束态描述，**用户点一下才真生图**。
- 判定为"否"的镜头完全不打扰，界面与今天一致。
- 判定理由与预填描述都进日志，便于统计命中率。

这一步的产出物不是功能，是**数据**：跑 3–5 个真实项目后你会看到「模型认为多少比例的镜头需要双帧」「它的理由站不站得住」，再决定要不要为它花图片配额。

### A 的落地顺序（B 之后才做）

1. 尾帧图必须复用本镜的同一组参考图与同一身份锚点生成（否则主体漂移）。
2. 只有当"本镜有状态变化 **且** 与下一镜不同景别衔接"时才自动出图；其余仍走自动衔接。
3. 请求素材优先级重定：手动尾帧 > 自动双帧（本镜起幅→止幅） > 前镜末帧衔接 > 身份参考 > 单帧。**这条是产品可见行为变更，做 A 前必须再要一次裁定**，否则会静默改变成片节奏。
4. 自动出图要有开关（默认关），并明确"多花一张图配额"。

## 6. 风险清单（按影响排序）

1. **判定通胀**：模型倾向对每个镜头都说"有变化"。缓解：判据写成"只有当画面里存在一个**可指认的物件状态或位置改变**才算，情绪/光影变化不算"，并在设置里可覆盖该条目（现有提示词规则机制）。
2. **两张静帧不一致**：同一镜头的起幅与止幅分别生成，主体/道具/天气可能各画一份。这是双帧方案最本质的风险，B 阶段无法暴露、A 阶段必然暴露。缓解：同参考图 + 同 seed + 止幅只描述"变化了的那一处"。
3. **与自动衔接冲突**：同一段视频既有止幅又从前镜末帧取起幅时，起幅就不是本镜画面图了。优先级不重定会出隐性 bug。
4. **成本与节奏**：图片量上升直接拉长步骤 4 的墙钟时间（免费档图片并发 3）。收益面却比裁定 2 那次小得多——接缝问题已经解决。
5. **验收口径要跟着改**：现行判据「`hasLastFrame:true` 的请求数 == 用户手动设双帧的镜头数」是**为验证 Task 2 拆错路径而设的**。A 一旦落地，这条要改成「== 判定为真并成功出图的镜头数」，否则会误判成回归。
6. **刷新降级**：末帧与止幅都是本地产物，不落持久化；刷新后自动退回单帧是既定行为，别当故障查。

## 7. 同类问题：还有哪些"手动开关"适合改成"模型判断 + 用户覆盖"

你真正说的诉求可能不止双帧。按"自动化收益 / 实现成本"给个初筛，供你一起研究：

| 手动项 | 能不能交给模型判 | 建议 |
|---|---|---|
| 双帧勾选 + 尾帧图 | 能（本方案） | 先 B 拿数据 |
| 视频一致性策略选 `off/chain/identity` | 部分能：同场景连续动作→chain，跨场景换主体→identity | 低优先，现状默认 `chain` 已够用 |
| 步骤 2/3/4 的「审核通过」卡点 | 不该自动化——那是用户话语权，不是判断题 | 保持手动（`全自动`模式已经提供绕过） |
| 失败镜头的「重试失败项」 | 不该自动重发（按秒/按张计费，裁定 3 已定） | 保持手动 |
| 某镜是否重摇 | 能：出图自检（构图/主体数/景别是否被压平）后给"建议重摇"标记 | 与 B 同一批做，成本极低（只加标记不生图） |
| 景别跳档时是否衔接 | 已自动化（相邻档判定），用户可关 | 保持 |

## 8. 怎么验证（不写代码也要先定判据）

- **离线**：统计日志里"模型判定需要双帧"的镜头占比与理由文本。合理量级应远小于 100%（若接近全部命中即判据失效）。
- **在线小样本**：同一个 90 秒三幕想法，两臂各跑一遍，比较接缝与镜头内收束的观感；抽帧比对同镜起幅/止幅的主体一致性。判据用相对值（同项目 A/B 对照、逐镜打分），不设"0 次漂移"这类绝对阈值。
- **成本口径**：报告图片张数与墙钟时间增量时，必须同时给并发设置与套餐（免费档 1 RPM 视频、图片并发 3），否则数字不可比。

## 10. 本次排查发现的遗留问题（已登记，未修）

1. **服务层诊断文案仍是硬拼中文串**：`videoService.ts` 5 处、`renderService.ts` 2 处（如「Video API 未返回 video_id」「视频任务 … 持续不存在…轮询 URL…」「下载视频失败 HTTP」「FFmpeg 日志尾部」）。它们会随 `err.message` 落到 `Shot.error` / 项目错误上成为界面文本。按规范的正确形态是：错误类携带 `code` + 结构化诊断字段，**展示层**再按 i18n 键翻译格式化；简单换成 i18n 串只是把问题挪个位置。建议单列一轮改造。`console.warn` 里的中文是日志，按规范不需要进字典。
2. **"渲染文本收口"缺一条能失败的测试**：本轮就是因此漏过一处——Task 8 明写要逐个确认 `appendRegistryRules` 调用点，我只改了视频路径就宣称完成，而 `tsc` / 530 用例 / `build` 全绿，因为没有任何断言检查"图片请求体里不含作者向条目正文"。补法：对生图与生视频的最终 prompt 断言不含条目特征串（`Keep negative prompts`、`when composing`、`注册表`、`骨架`）。**这条不补，以后还会漏。**
3. **单项重摇与批量路径曾不同口径**：批量失败提示带"可手动重试"，单项重摇路径没带（本轮已修）。沉淀为规则：任何提示/收口改动必须同时核对批量、单项、重试、手动四个入口。
4. **A 方案有个尚未计入的隐性优势**：止幅若是**生成的远程图片 URL**，它就能持久化、刷新不丢，不像末帧那样是本地 blob。反过来说，B/A 的判断字段（`needsDualFrame` / 结束态描述）都是镜头内容，必须进 `ShotContentFields`（`shotFields.ts` 是显式清单，漏加就等于静默丢弃——Task 1 已经踩过一次）。

## 11. 同域已知缺口（明确不属于本方案）

- 批量生成**没有用户级取消入口**，切项目/离开步骤不中断在飞请求与轮询（`AGENTS.md` 铁律注 + `docs/execution-flow.md` §9.3）。
- CI **不跑测试**，质量门禁只在本地。
- 跨镜头**空间几何一致**：2026-09-23 四臂 A/B 已实测否决"加场景参考图"，剩余候选未定，需另立方案。
- 角色识别特征（眼罩）属性绑定失败属模型能力边界，本方案不涉及。
