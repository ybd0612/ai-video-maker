# 分镜 / 图片 / 视频 三页布局重排方案（双栏骨架）

> 状态：**已定稿（2026-09-23），待实施**。§16 的五个开放问题已全部拍定，实施计划见 `2026-09-23-wizard-layout-redesign-plan.md`。
> 设计基准：**1920×1080**（用户确认）。
> 范围：**纯前端展示层**。不改生成链路、不改请求体、不改 store 数据结构、不碰计费路径。
> 关联：`2026-09-23-auto-dual-frame-design.md`（双帧自动化，与本方案在"视频页右栏"有交集）、`docs/execution-flow.md`、`AGENTS.md`「UI 交互约定 / 编码规范」。

## 1. 症状与取证

先结论：**"不好看"不是一个原因，是四个独立缺陷叠在一起**。每条都有 `文件:行` 证据，且我自己逐条复核过（不是推测）。

| 症状 | 事实 | 证据 |
|---|---|---|
| 内容被锁在窄带里，右边大片空白 | 三页顶层都是同一个容器：居中、`max-w-4xl`、无水平内边距。注意本项目根字号是 112.5%，Tailwind 的 rem 按实际根字号解析 → **56rem ≈ 1008px**（不是 16px 基准下的 896px） | `StepStoryboard.tsx:199`、`StepImages.tsx:62`、`StepVideos.tsx:78`、`globals.css:17` |

| 长文本要么全铺要么看不见 | 详情里的中文长提示词全量铺开、**不折叠不 clamp**；列表侧一律 truncate —— 中间档不存在，而仓库里现成的折叠组件**零引用**（死代码） | `AssetEditorTemplate.tsx:150,157,181`、`ShotCard.tsx:66`、`ExpandableSection.tsx`（全仓无调用方） |

⚠️ 关于 token 塌缩必须说清楚：注释表明它是**刻意**的（"浅色下与 line 同级，保证模块分割线可见"、"双主题同值"）。所以不能简单"把颜色拉开"了事 —— 那会破坏当初的动机。正确解法见 §8。

## 2. 目标与非目标

**目标**
1. 消掉"来回跳"：详情常驻，镜头可横向比较（看 5 镜改 6 镜不用翻页）。
2. 消掉"无限长滚"：滚动切成两个有界区。
3. 一眼可见的质感提升：层级真的分得出主次、9:16 素材按 9:16 显示。
4. 三页像同一个产品：一套头部、一套进度、一套错误、一套审核卡点。
5. 让本轮建立的口径可见：景别、衔接/尾帧状态、任务与失败原因。

**非目标**
- 不改任何生成行为、请求参数、计费与恢复逻辑（视频页的按钮语义保持现状）。
- 不引入 UI 组件库、不引入 CSS-in-JS、不新增状态管理。
- 不做响应式移动端口径（桌面工具；只保证窄窗口不崩）。
- 不借这次重排改数据模型；若某项展示需要新字段，另立方案。
- 不动步骤 1/2/6 的页面结构（只在共享件层面受益）。

## 3. 骨架：左镜头轨 + 右常驻详情

```
┌ 顶栏：项目名 · 步骤指示 · 本页批量动作（一枚主 + 至多两枚次） ─┐
├───────────────┬──────────────────────────────────────────────┤
│  镜头轨        │  详情区（当前镜头，独立滚动）                  │
│  2 列 9:16     │  ┌──────────┐  ① 主媒体块（按画幅）            │
│  竖略图        │  │ 真实比例 │  ② 状态与进度（三页同一组件）      │
│  ┌──┐┌──┐     │  │ 预览区   │  ③ 摘要 / 对白                   │
│  │01││02│W M  │  └──────────┘  ④ 提示词（折叠档）              │
│  └──┘└──┘     │  ⑤ 本页专属动作（重摇 / 双帧 / 参考图）         │
│  紧凑切换      │                                              │
│  （独立滚动）  │                                              │
├───────────────┴──────────────────────────────────────────────┤
│ 底栏：上一步 · 审核卡点（同一组件，三页都有） · 下一步          │
└──────────────────────────────────────────────────────────────┘
```

设计要点：
1. **容器不再锁 896px**：外层放开到可用宽度的百分比上限，双栏各按 `flex` 比例分配。左轨按内容定宽，右栏吃掉剩余 —— 等于把今天白扔的右侧空间变成生产力，**不是挤现有内容**。
2. **两个独立滚动区**：轨自己滚、详情自己滚，页面主体不再无限长。这是治"太长要滚"的主刀。
3. **景别/状态上轨**：略图右下角一个字符级景别标记（远/全/中/近/特）+ 一枚状态点 → 一眼看出"连着三镜都是中景"这类节奏问题。
4. **选中态用边框 + 底色双重编码**，不只靠颜色（无障碍）。
5. 三页共用同一个骨架，页面差异**只落在右栏①与⑤两块**。

## 4. 组件边界（谁负责什么）

新增 4 个共享件（各一个职责，可独立理解）：

| 组件 | 职责 | 输入 | 不该做 |
|---|---|---|---|
| 向导双栏壳 | 顶栏 / 镜头轨 / 详情槽 / 底栏的槽位与滚动分区 | 镜头集合、当前选中、页名 | 不认业务、不读 store |
| 镜头轨 | 竖略图列表 + 景别/状态标记 + 选中与键盘导航 | 镜头集合、当前 ID、画幅 | 不渲染详情内容 |
| 步骤状态条 | 统一的"批量进行中"进度与计数表达 | 完成数 / 总数 / 色调语义 | 不决定何时显示 |
| 审核卡点（统一版） | 半自动卡点 + 完成态 CTA，三页同一实现 | 审核标记、是否全部就绪、回调 | 不改门禁判定逻辑（仍由 `canAdvance` 唯一裁决） |

要合并掉的重复：
- 4 处近似错误框 → 一个错误框组件。
- 2 套进度条（图片 accent / 视频 warn）+ 分镜缺失 → 步骤状态条一处。
- 2 套审核/确认 markup → 统一版审核卡点。
- 图片页与视频页各自重复约 50 行的"头部 + 重试失败 + 全部重摇"按钮组 → 壳的顶栏插槽。
- `ShotCard`（就地展开）与 `ShotDetail`（整页替换）两种详情形态并存 → 统一为"轨上条目 + 右栏详情"，卡片式就地展开不再作为主路径。
- 死代码 `ExpandableSection`：改造后**由它承担 §7 的折叠档**；不承担就删（不留二次死账）。

约束：合并只搬 markup 与样式，**不改任何回调与写回逻辑**；异步写回仍一律按项目 ID。

## 5. 三页右栏的差异

| 页 | ① 主媒体块 | ⑤ 专属动作 | 新增可见项 |
|---|---|---|---|
| 分镜 | 无媒体 → 改为「文案 + 双提示词」为视觉主角，脚本用可读字号成段显示 | 交给 AI 修改、删除、对白编辑 | 景别、时长、资产引用数、衔接预告（本镜是否会取前镜末帧） |
| 图片 | 真实画幅出图（左）+ 参考图条（右，带角色/主体/道具标签） | 生成 / 重摇、4 个画面子字段 | 参考位分配（哪几张进了参考、因景别被拒的是哪张） |
| 视频 | 播放器按真实画幅，未出图时用同比例占位而非扁条 | 生成 / 重摇、双帧控件、（若做末帧质检）质检结论 | 服务端任务状态与 ID、失败原因、`videoProgress`、末帧是否已抽到 |

视频页**必须补上完成 CTA**（现在只能靠底部"下一步"），并让它在全部就绪时可见。

## 6. 画幅自适应版式（9:16 为主）

1. 所有媒体容器由 `project.aspectRatio` 派生一个比例常量，**不再各自写死 `max-h-48` / `h-24`**。
2. 版式规则：竖幅(9:16) → 详情区左侧留固定比例列、轨上略图为竖条并排两列；横幅(16:9) → 预览改为通栏，轨上略图变横条；正方(1:1) → 单栏方形。
3. 9:16 在详情区按"高度优先"缩放（受可视高度约束），**而不是按宽度撑满后被 max-h 截断** —— 后者正是今天两侧留白的原因。
4. 占位块用同比例的虚线框，不用固定 6rem 高的横条。
5. 黑底占位（现在的原始色字面量）改成语义 token，深色主题下才不刺眼。

## 7. 信息密度与折叠三档

长中文提示词是本项目主要文本负载，今天只有"truncate"和"全量铺开"两个极端。改成三档：

- **档 1 轨上**：无正文，只有序号 + 景别 + 状态点。
- **档 2 详情区默认**：摘要 + 提示词各 3 行 clamp + 「展开」；展开后不跳页，原地增高。
- **档 3 需要时**：全文 + 换行保留（生图/生视频文本要能看清单行结构）。

规则：默认落在档 2；同一页内**不做自动折叠**（自动折叠=不可预期），展开状态只在切换镜头时复位。

## 8. 视觉层级与 token 修正

问题不是"颜色选错了"，是**档位塌缩**。做法（不破坏原动机）：

1. **文字四档真正拉开**（取值已定，见计划 Task 1）：浅色主题 `--c-ink-4` 由 `#64748b` 改为 **`#7b8a9d`**（在 `bg-app/raised/surface` 上对比度约 3.1:1，够用于非关键信息），`--c-ink-5` 保持 `#94a3b8`。用途边界写进 AGENTS.md：ink-4 只用于计数、进度百分比、图标按钮标题等**非关键信息**，正文与可读文本一律 ink-2 / ink-3。
2. **边框两档各归其位**（取值已定）：`--c-line` 保持 **`#e2e8f0`**（外框与模块分割线，沿用原注释动机），`--c-line-soft` 改为 **`#eef2f6`** 只用于内部分隔（子字段之间、卡片内小节之间）。两者不再同值，但分割线可见性不被削弱。
3. 深色主题已经分得开，不动。
4. **卡片质感统一配方**（一次改，全项目受益）：浮起层底色 + 一档更弱的边框 + 一致的圆角与内距 + 明确的 hover/selected 两态。今天三页的卡片内距与圆角并不一致。
5. 图标尺寸改为跟随根字号缩放（用尺寸类而非 px 传参），否则整体缩放时文字变大、图标不变。
6. 状态色语义固定下来：进行中=警示色、成功=成功色、失败=危险色、AI 建议=强调色。**同一语义在进度条上不许换色**（现在是图片 accent / 视频 warn 表示同一件事）。

## 9. 状态、进度与错误一致性

- 一套镜头状态映射（已有的复用），三页共用；新增的"任务已创建待恢复""末帧已就绪/已丢失"要能在界面上读出来。
- 步骤级进度用步骤状态条：完成数 / 总数 + 预计剩余（若现有数据不足则只显示计数，**不编造 ETA**）。
- 失败信息分层：一句话原因（界面上）+ 详情（折叠里），不再把整段服务端文本糊进卡片。
- 失败重试计数不再出现"硬编码上限"字样（现在视频页有个写死的 `/3`）。

## 10. 本轮新口径要可见

1. **景别**：轨上字符标记 + 详情区一行"本镜景别 / 与上一镜是否同档"。标记必须与 `ShotSize` 枚举一一对应，不得自造档位：**极远（extreme-wide）/ 远（wide）/ 中（medium）/ 近（close）/ 特（close-up）**；缺字段时显示"未知"而不是猜一档。
2. **衔接**：详情区显示"本镜首帧来源：前镜末帧 / 本镜画面图（景别跨档，未衔接 / 末帧未就绪）"。这是你验收成片接缝时最需要知道的一件事，现在完全静默。
3. **参考位分配**：图片页显示"因景别被拒收的道具图"，否则用户只会觉得"我明明勾了道具，怎么没照它画"。
4. **任务恢复**：视频页显示是否存在服务端任务（有则刷新可续，无则需重做）—— 与计费直接相关，值得占一行。

## 11. 响应式与退化

- ≥1440：轨 2 列宽裕，预览可按高度放大。
- 1024–1440：轨 2 列 + 紧凑切换（只留序号行）；预览保持比例优先。
- <1024（含窄窗）：轨退化为**顶部横向条**（方案 B 的形态），详情仍在下方常驻 —— 而不是丢掉详情回到整页替换。
- 紧凑态与展开态是否记忆到用户设置：**待你拍板**（§16-Q2）。

## 12. 可访问性（既有约定不许退化）

- 卡片"进入编辑 = 点整张卡"的约定保留（`role=button` + `tabIndex` + Enter/Space + 语义化 focus 边框）。
- 卡内次级操作仍必须阻止冒泡。
- 双栏下键盘导航规则：轨 `↑↓` 换镜、`Tab` 进详情；详情内焦点不劫持翻页。
- 选中态不得只靠颜色（§8 已要求双重编码）。
- AI 辅助入口仍内嵌在输入框内，不得借重排改回旁挂式。
- 所有新文案进 i18n，`zh` / `en` 同步补齐。

## 13. 性能验证（不拍阈值）

本项目不以浏览器做界面核对，但布局重排的代价必须可测：

- **可测部分（我在本地能给的）**：镜头集合 → 轨/详情渲染的纯逻辑单测（选中、折叠态、按画幅派生尺寸、状态映射）；构建产物体积变化（新增共享件不应让包体明显变大，给相对数字）。
- **需要你本地配合的部分**：12 / 20 / 40 镜三档项目，各记录首次可交互与滚动手感。**判据用相对值**：与改造前同项目同机器对比，不引入"必须 <N ms"这种凭经验阈值。
- **虚拟滚动的取舍交给实测**：只有当 40 镜档确实出现可感知卡顿时才引入；不预先上虚拟化（它会带来图片加载与键盘导航的新复杂度）。
- 图片懒加载与解码策略属于"顺手该有"，不算性能优化承诺。

P0 与 P1 无依赖关系，可并行；P2 依赖 P1；P3 依赖 P2。

## 15. 风险与回滚

1. **改 token 会波及全站**（步骤 1/2/6、设置弹窗、日志坞都用它）→ P0 单独一期，改完立刻全站扫一遍对比度，尤其浅色主题的弱文字不能低到看不清。
2. **放开 896px 会让长文本行变超宽**（可读性下降）→ 正文行宽设上限（不跟着视口无限变长）。
3. **双栏后小窗口详情被挤** → §11 的横向条退化态兜住。
4. **审核卡点统一会改变"半自动"的推进手感**（视频页原本没有卡点）→ 这是产品可见变化：只补"完成 CTA"，**不给视频页新增强制审核闸门**（`canAdvance` 步骤 5 的判定保持不变）。
5. **合并组件容易顺手改行为**（本项目最大风险）→ 约束：P1 的 commit 里不允许出现回调/写回/请求逻辑改动；review 时按 diff 逐条核对。
6. 每期都是独立提交，出问题回滚当期即可，不必回退整个重排。

## 16. 已定决策（原开放问题，2026-09-23 拍定）

1. **左轨宽度与列数**：按 1920×1080 设计 —— 轨宽 `15.5rem`（≈279px），**固定两列 9:16 竖略图**；提供「紧凑（只留序号行）」手动切换，**默认不启用**。1024 以下按 §11 退化为顶部横向条。
2. **紧凑/展开态是否记忆**：**不记忆**，每次进页回到默认（两列 + 档 2 折叠）。少一个持久化字段、少一次迁移、少一类"刷新后界面不一样"的困惑。
3. **是否先单独做 P0**：**不单独停下来等确认** —— P0/P1/P2/P3 在一次长任务里连续执行；但每期各自独立提交，任一期出问题可单独回滚。P0 完成时会有一次自然停顿点（token 与画幅版式），若届时肉眼不认可，后续期次照做不影响回滚。
4. **三页右栏是否合成一个详情组件**：**不合并**。只共用壳（`WizardShell`）、轨（`WizardRail`）、进度条、错误框、审核卡点；右栏内容各页自己写。理由：三页右栏的语义差异远大于相似点（分镜是文本、图片是出图+参考位、视频是播放器+任务状态），强行合一会把三套差异塞进一个组件的布尔开关里 —— 那正是本项目「同一语义一个权威实现」所反对的反面。
5. **步骤 2（资产）是否纳入**：**不纳入双栏**。它只复用统一后的错误框与审核卡点（P1 顺带收益）。理由：资产页已是 `AssetDetailShell` 容器查询双栏，结构问题不存在；纳入只会扩大改动面。

## 17. 实施硬约束（由代码核查得出，违反会静默出事）

1. **布局逻辑必须下沉到纯函数**。本仓库 Vitest 配置是 `environment: "node"`、`include: ["tests/**/*.test.ts"]`（不收 `.tsx`）、**没有 jsdom / happy-dom / @testing-library**，全仓 `tests/` 无一处 import 组件。所以 JSX 本身不可测 —— 凡是可判定的东西（画幅→尺寸、景别标签、首帧来源解释、轨选择与键盘导航、折叠态复位）都进 `src/lib/*.ts` 并写单测；纯样式重排靠 `tsc` + `build` + 530 既有用例 + 用户本地目测，**不得假装组件测试存在**。
2. **不得让步骤组件重新挂载**。三页各有 `[shots.length]` 依赖的自动生成 effect（`StepImages.tsx:40-45`、`StepVideos.tsx:56-61`、`StepStoryboard.tsx:103-129`）与"从缺到齐"边沿检测的 `prev` ref（如 `StepVideos.tsx:41-51`）。壳必须**在各步骤组件内部**渲染（页面持有选中态），而不是把步骤换成路由级子组件 —— 后者会重挂载、`prev` 初值取当前值、批量生成再触发一次（会烧配额）。
3. **滚动归属只有一层**。滚动权在 `CreationWizard.tsx:92` 的 `flex-1 overflow-y-auto`（`main` 与 `body` 都是 `overflow-hidden`）。双栏各自 `overflow-y-auto` 必须建在这层之下，且外层该容器在双栏激活时不再自身滚动（否则出现双滚动条嵌套）。
4. **审核位不能被绕过**：`imagesReviewed` / `storyboardReviewed` / `assetsReviewed` 只在原 confirm 回调里写；重构若绕过这些回调，`canAdvance` 会永久为 false（`CreationWizard.tsx:48-63`）。
5. **Lightbox 是 body 级 fixed 副作用**（`src/components/ui/Lightbox.tsx`），轨容器上**不得加 `transform` / `filter`**，否则其 fixed 基准被改写。
6. **待办计数必须复用同一 SSOT**：`pendingImageShots` / `pendingVideoShots`（`src/lib/shotQueue.ts`）。轨上任何"待补做"徽标不许自己 filter 一遍，否则按钮显示 N、批量实际做 M。
7. **视频 `videoUrl` 是远端地址不是 blob**，虚拟化/懒挂载不会造成 blob 泄漏；但**步骤 6 的成片预览不能"卸载重建"**（`StepAssembly.tsx:31-53` 已手工管 revoke 与活动项目切换释放）。
8. **i18n 硬规则**：`en` 字典的键必须与 `zh` 完全一致（TS 类型强制，缺键直接编译不过）；插值是**单次替换**，同一占位符在一条文案里只能出现一次。
9. **`shotStatus` 的色已在 `shotStatus.tsx:9-18` 定义为 `text-ink-4/info/accent/warn/danger`** —— P0 改 token 值会同时改变状态徽标的观感，必须一并核对，不能只当排版改动。
10. **不新增依赖**：仓库无虚拟列表库（`react-window` / `@tanstack/*` 均未安装）。是否引入虚拟滚动由 §13 的实测决定，本方案默认不做。
